# T-015f accessibility audit

Checked the player home, workout focus mode and rest timer, nutrition today,
progress, player shell and bottom navigation, install sheet, PR burst, captain
roster, inbox, and program builder. No layout redesign or dependencies added.

## Fixes and verification

- Shared controls: retained the existing token-based global `:focus-visible`
  outline; disabled transitions under reduced motion; labelled stepper outputs,
  isolated their numbers, and made field errors alerts. Existing sync pills use
  `role="status"`; media and roster radar errors now use `role="alert"`.
- Player home: native week list and isolated English date/day labels. The start
  button's existing glow already disables animation under reduced motion.
- Focus mode: removed the heading-order inversion and redundant RTL declaration.
  Timer output has live announcements disabled. A persistent status outside the
  rest panel announces start, one final-ten-seconds message, and completion,
  including after the panel unmounts. Tests cover timestamp-independent phases,
  short/resumed rests, inactivity, and skipped rests. Set controls and timer
  actions are at least 64px; existing steppers are 76px and done is 68px.
- Exercise GIFs: hidden under reduced motion, with exercise names and existing
  Gym visual attribution retained. No static poster assets exist in this scope.
- Nutrition today: native meal list; macro numbers and English abbreviations
  use `bdi` instead of setting direction on whole blocks. Meal toggles already
  expose `aria-pressed`; empty/loading/error states were present.
- Progress: kept the update opener mounted and focusable, including after a
  successful update; photo picker labels expose the hidden input's focus ring.
  The native modal sheet can close on Escape during upload as well.
- Player shell / bottom nav: existing Arabic labels, 48px targets, current-page
  semantics, sync status, and loading/error states checked. English captions are
  isolated. Root `lang="ar" dir="rtl"` already exists and was left untouched.
- Install sheet: native `showModal()` already provides focus containment, Escape
  cancellation and opener restoration; labelled heading and error alert present.
- PR burst: existing Arabic dismiss label, status, 48px target, `motion-safe`
  confetti and `motion-reduce:hidden` checked.
- Captain roster: existing labelled archive controls and native invite modal
  checked; removed redundant RTL; radar failures now alert.
- Captain inbox: native modal on mobile makes background content inert and traps
  focus; native nonmodal detail panel keeps desktop layout. Escape dismisses,
  close restores the opener, and a focusable heading is the fallback after a
  reviewed row disappears. Native task list added. Lifecycle tests cover both
  modes, cleanup, Escape, cancellation and missing openers.
- Program builder: unique Arabic move/delete labels include exercise/day context
  and position; added the missing level-two day heading and native exercise list.
  Existing toggles, library attribution and async states checked.

## Contrast

WCAG sRGB luminance, conservative upper bound: full 8% lime glow over the
brightest navy mesh (`23 34 46`), then white 5% glass; also checked two nested
glass layers, black 40% strong glass, and the solid fallback.
Only `--color-muted` changed, from `#9aa0a6` to `#b0b6bc`:

| Surface | Before | After |
| --- | ---: | ---: |
| Glass | 4.34:1 | 5.60:1 |
| Nested glass | 3.73:1 | 4.81:1 |
| Strong glass | 6.43:1 | 8.30:1 |

The colour-token regression test checks the 4.5:1 minimum. Glass utilities were
not edited. This is a conservative calculation, not a browser pixel measurement.
